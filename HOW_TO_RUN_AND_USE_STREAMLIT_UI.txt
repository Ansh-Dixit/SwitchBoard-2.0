2. COMPLETE GUIDE TO ALL TABS & FUNCTIONS IN THE STREAMLIT UI
--------------------------------------------------------------------------------
The Streamlit application (`switchboard/app/streamlit_app.py`) is organized into
THREE main tabs at the top of the page:

  [Tab 1] "1. Interactive Demo & Switch-Boundary Inspector"
  [Tab 2] "2. Saved Benchmark Results & Error Analysis"
  [Tab 3] "3. Annotation Sheet, Normalization & Walkthrough"

Below is what every section, button, dropdown, and table on each tab does.

--------------------------------------------------------------------------------
TAB 1: INTERACTIVE DEMO & SWITCH-BOUNDARY INSPECTOR
--------------------------------------------------------------------------------
This tab lets you test individual Hindi–English utterances, play audio, compare
Baseline Whisper Small against our Fine-Tuned Whisper Small (PEFT LoRA +
Auxiliary Language Identification Head), edit word-level language tags, and
visually inspect word errors right at language-switch boundaries.

A. "Step 1: Select Audio Source" (Top-Left Panel)
   You have 4 radio-button options for choosing the input audio:

   1) "Real MUCS 2021 Hindi–English Corpus (517 Held-Out Test Utterances)"
      - Default mode when your extracted MUCS 2021 dataset is present.
      - Displays a dropdown list of real human-spoken Hindi–English lecture
        utterances from the held-out test speakers (`mucs_834022`, `mucs_847066`,
        `mucs_918821`, `mucs_921151`, `mucs_957491`).
      - Selecting any utterance loads its real 16 kHz mono WAV audio clip, its
        reference transcript, its word-level HI/EN/OTHER language tags, and the
        Baseline vs. Fine-Tuned model hypotheses.

   2) "Bundled Hinglish Examples (Ready-to-Try Demo Fixture)"
      - Lets you choose from the 5 self-contained demo fixture test utterances,
        starting with the canonical example:
        `demo_test_utt_01: "kal meeting ke baad main report submit kar dunga"`
      - Useful for demonstrating specific edge cases in class:
        * `demo_test_utt_01`: Overlapping switch boundary on "meeting"
          (`kal [HI] -> meeting [EN] -> ke [HI]`) and same-language continuation
          (`report [EN] -> submit [EN]`).
        * `demo_test_utt_02`: Same sentence written completely in Devanagari
          (`"आज मीटिंग के बाद मैं रिपोर्ट सबमिट कर दूंगा"`) to demonstrate
          cross-script normalization (`"मीटिंग"` -> `"meeting"`).
        * `demo_test_utt_03`: Proper name (`"Rahul"`) + hesitation filler
          (`"umm"`) tagged as `OTHER` to show that `OTHER` tokens do not trigger
          false language switches.
        * `demo_test_utt_05`: Monolingual Hindi control sentence (`CMI = 0`),
          showing that `Boundary WER` is automatically marked `"Unavailable (0/0)"`
          when an utterance has zero language switches.

   3) "Upload Audio File (.wav, .mp3, .flac)"
      - Opens a drag-and-drop file uploader.
      - When you upload any `.wav`, `.mp3`, `.flac`, or `.ogg` file, SwitchBoard
        automatically converts stereo to mono, resamples the audio to 16,000 Hz
        16-bit PCM WAV, computes its duration in seconds, and loads it into the
        audio player.
      - You can test this immediately by uploading any `.wav` file from:
        `C:\Users\Manas Nigam\Desktop\SwitchBoard\data\processed\audio_16k\mucs2021_hi_en\test\`

   4) "Record via Microphone"
      - Renders Streamlit's built-in browser microphone recorder (`st.audio_input`).
      - Click the microphone icon, grant browser microphone permission, speak a
        Hindi–English sentence (e.g., "kal meeting ke baad main report submit kar dunga"),
        and click Stop.
      - SwitchBoard automatically resamples your live recording to 16 kHz mono WAV
        and runs the comparison pipeline.

B. "Checkpoint & Availability Settings" (Top-Right Panel)
   1) "Fine-Tuned Whisper Checkpoint" Dropdown:
      - "Demo / Smoke-Test Fine-Tuned Adapter (LoRA + LID Head)": Uses the fast
        adapter checkpoint.
      - "Full Research Corpus Checkpoint": Uses the checkpoint trained on your
        3,136-utterance MUCS 2021 dataset (`outputs/full_checkpoints/whisper_small_lora_plus_lid`).
      - "Simulate Fine-Tuned Checkpoint Unavailable (Test Graceful Fallback)":
        Select this during your presentation to demonstrate requirement 6.2 —
        the app displays a clear yellow warning banner showing that the
        fine-tuned checkpoint is unavailable while keeping the Baseline Whisper
        transcription and boundary evaluation 100% usable.

   2) "Run Live Neural Inference on Audio" Checkbox:
      - Unchecked (Default): Loads pre-computed benchmark hypotheses instantly
        so you can click through utterances with zero waiting latency during a
        live presentation.
      - Checked: Runs a live PyTorch forward pass through the loaded PEFT model
        weights on the selected audio file.

C. Audio Player Bar
   - Plays the active 16 kHz mono WAV file directly in the browser (`st.audio`).

D. "Step 2: Side-by-Side ASR Output Comparison"
   - Left Column ("Primary Baseline: openai/whisper-small"):
     * Shows the raw transcript produced by Baseline Whisper Small.
     * The text box is interactive/editable: you can type or modify words inside
       it during a demo to show how adding/removing errors changes the alignment
       and Boundary WER in real time!
     * Below the box, it displays the **Normalized Baseline** text (after
       Unicode NFC, punctuation removal, lowercasing, and cross-script mapping)
       along with the checkpoint name, decoding mode (`task='transcribe'`),
       transcription latency (seconds), and Real-Time Factor (`RTF`).
   - Right Column ("Fine-Tuned: Whisper Small + PEFT LoRA + Auxiliary LID Head"):
     * Shows the raw and normalized transcript from the fine-tuned model side by
       side with Baseline Whisper, plus its latency and RTF.

E. "Step 3: Reference Transcript & Word-Level Language Tag Review (HI, EN, OTHER)"
   1) Reference Transcript Input Box:
      - Shows the ground-truth reference sentence. You can edit this or type a
        reference transcript for an uploaded/recorded audio clip.
   2) Interactive Word-Level Language Tag Editor Table (`st.data_editor`):
      - Displays 4 columns for every word in the reference transcript:
        * `Index`: 0-based word position (`0, 1, 2, ...`).
        * `Raw Reference Word`: The original word as written in Devanagari or Roman script.
        * `Normalized Form`: What the word normalizes to via `configs/normalization_equivalents.yaml`
          (for example, `"मीटिंग"` or `"क्लिक"` normalizes to `"meeting"` or `"click"`).
        * `Reviewed Language Tag`: An interactive dropdown cell where you can
          click and change any word's tag between `HI`, `EN`, and `OTHER`!
          When you change a tag in this table, the switch-boundary badges and
          Boundary WER below update immediately.
   3) "Switch-Boundary Word Highlighting (HI -> EN and EN -> HI)" Badges:
      - Renders every reference word as a visual pill with its language badge:
        * Blue pill (`HI`) = Hindi word
        * Green pill (`EN`) = English word
        * Gray pill (`OTHER`) = Proper name, filler (`umm`, `हम्म`), number, or software name
      - Words immediately before or after a language switch get an orange border
        and lightning badge:
        * `⚡Pre` = Word immediately BEFORE a language switch
        * `⚡Post` = Word immediately AFTER a language switch
        * Red border + `⚡⇄2x-Switch` = Overlapping boundary word touched by TWO
          switches (e.g., `"meeting"` in `"kal [HI] meeting [EN] ke [HI]"`).
          Counted only ONCE in the pooled Boundary WER denominator!
   4) "Word-Level Alignment & Edit Attribution (MATCH, SUB, DEL, INS)":
      - Compares the Baseline alignment (left) vs. Fine-Tuned alignment (right)
        using color-coded operation badges:
        * Green `✓ word ⚡`: Exact match (`MATCH`)
        * Red `SUB [ref -> hyp] (ref#i⚡)`: Substitution error assigned to reference word `i`
        * Pink dashed `DEL [ref -> ∅] (ref#i⚡)`: Deletion error assigned to reference word `i`
        * Purple `INS [+ hyp] (attr->ref#i⚡)`: Insertion error deterministically
          attributed to reference position `i = max(0, cursor - 1)`
      - Beneath each alignment, 4 KPI metric cards display:
        * `Norm Overall WER`: Normalized Word Error Rate `%(errors/words)`
        * `Raw Overall WER`: Pre-normalization Word Error Rate `%(errors/words)`
        * `Boundary WER`: Error rate specifically on switch-adjacent words `%(errors/boundary_words)`
        * `Non-Boundary WER`: Error rate on non-switching words `%(errors/non_boundary_words)`
      - The bottom caption shows the utterance's **Code-Mixing Index (CMI)**,
        CMI regime bucket, number of switches, switch directions, and overlapping
        boundary word count.

TAB 2: SAVED BENCHMARK RESULTS & ERROR ANALYSIS
--------------------------------------------------------------------------------
This tab loads the saved corpus evaluation files from disk and displays aggregate
research metrics.

1) "Select Benchmark Result Tier" Radio Selector:
   - "Full Research Corpus Benchmark (`outputs/full_benchmark`) — [REAL MUCS 2021 CORPUS: 517 Held-Out Test Utterances]" (Default)
     * Loads the benchmark evaluated on the 517 held-out test utterances (6,559
       words, 2,852 switch-boundary words) from your `Hindi-English_test.tar.gz` dataset.
   - "Demo Fixture Benchmark (`outputs/demo_evaluation`) — [DEMO FIXTURE: 5 Test Utterances]"
     * Loads the self-contained 5-utterance test fixture results (kept strictly
       separate from full research results).
   - "Live Smoke-Test Evaluation (`outputs/live_evaluation`) — [SMOKE TEST]"

2) "1. Model Comparison Table (Same Held-Out Test Split)":
   - Displays all 4 evaluated models side by side on the exact same test split:
     * `whisper_small_baseline` (`openai/whisper-small`)
     * `indicwhisper_hi_comparison` (`vasista22/whisper-hindi-small`)
     * `whisper_small_lora_only` (LoRA adapters in decoder attention, no LID loss)
     * `whisper_small_lora_plus_lid` (LoRA adapters + Auxiliary LID Head on decoder hidden states)
   - Columns include: Raw WER, Norm WER, Norm CER, Boundary WER, Non-Boundary WER,
     `HI->EN` WER, `EN->HI` WER, Pre-Switch WER, Post-Switch WER, Mean CMI, RTF,
     and `Boundary WER Improved?` (showing the exact percentage-point improvement).

3) Detailed Subgroup Breakdowns (Select any model from the dropdown):
   - 5 KPI Cards: Normalized WER, Raw WER (Pre-Norm), Boundary WER,
     Non-Boundary WER, and Mean CMI / RTF.
   - "Switch Direction & Position Breakdown" Table:
     * Compares `HI -> EN` vs. `EN -> HI` switch directions and `Word Immediately
       Before Switch` vs. `Word Immediately After Switch`, showing exact `Errors`,
       `Words`, and `S / D / I` counts.
   - "Error Rates Across Code-Mixing Index (CMI) Ranges" Table:
     * Buckets utterances into `0 (Monolingual)`, `0-15 (Low Mixing)`,
       `15-30 (Moderate Mixing)`, and `>30 (High Mixing)` and reports Pearson
       correlation `r` between utterance CMI and WER.
   - "Breakdown by Speaker ID" & "Breakdown by Accent" Tables:
     * Shows per-speaker WER, Boundary WER, and Non-Boundary WER across the
       held-out test speakers (`mucs_834022`, `mucs_847066`, `mucs_918821`,
       `mucs_921151`, `mucs_957491`).
   - "Per-Utterance Results Table":
     * Searchable, sortable dataframe of all 517 evaluated test utterances.

--------------------------------------------------------------------------------
TAB 3: ANNOTATION SHEET, NORMALIZATION & WALKTHROUGH
--------------------------------------------------------------------------------
1) "Sample Reviewed Word-Level Annotation Sheet":
   - Renders `docs/sample_annotation_sheet.csv`, showing how ambiguous words
     (like Romanized `"main"`, Devanagari English `"मीटिंग"`, proper names like
     `"Rahul"`, and vocal fillers like `"हम्म"`) are annotated and why script
     alone cannot determine language.
2) "Verified Baseline & Comparison Checkpoints":
   - Shows the live verification table of all registered models, their licenses,
     language coverage, and explicit CTC head dependency status (highlighting
     that `facebook/wav2vec2-xls-r-300m` requires training a CTC head before
     transcription, whereas `Harveenchadha/vakyansh-wav2vec2-hindi-him-4200`
     includes a trained CTC head).
3) Expandable viewers for `docs/ANNOTATION_GUIDELINES.md` and
   `configs/normalization_equivalents.yaml`.


3. ALL TERMINAL / CLI COMMANDS FOR RUNNING TESTS, TRAINING & EVALUATION
--------------------------------------------------------------------------------
Run any of these commands from `C:\Users\Manas Nigam\Desktop\SwitchBoard`:

  # Run the 11 automated unit & integration tests (pytest)
  python -m pytest -v

  # Validate the 3,136-utterance real MUCS 2021 manifest and audio files
  python -m switchboard.cli validate-manifest --manifest data/full_corpus/unified_manifest.jsonl --check-audio

  # Re-run switch-boundary evaluation on all 517 held-out real MUCS 2021 test utterances
  python -m switchboard.cli evaluate-real-mucs --max-utterances 517

  # Re-run evaluation on the 5-utterance demo fixture
  python -m switchboard.cli evaluate-demo

  # Train Whisper PEFT LoRA alone vs. LoRA + Auxiliary LID Head on the real corpus
  python -m switchboard.cli train --config configs/train_smoke_lora_only.yaml --manifest data/full_corpus/unified_manifest.jsonl --output-dir outputs/full_checkpoints/whisper_small_lora_only
  python -m switchboard.cli train --config configs/train_smoke_lora_lid.yaml --manifest data/full_corpus/unified_manifest.jsonl --output-dir outputs/full_checkpoints/whisper_small_lora_plus_lid

  # Verify model checkpoints, licenses, and CTC head status
  python -m switchboard.cli verify-models
